## §0. 결론부터 — 이번엔 **내가 틀렸고, 그 지적이 숨은 고장을 찾아냈다**

Gemini 2차 #1: "현행 `x(축수/5)` 는 축의 **가중치를 무시한다.** 한국에서 가치는 35%,
모멘텀은 10%인데 어느 쪽이 빠져도 똑같이 x0.8 이다."

1차에서 내가 쓴 반박은 "제안들은 전부 지금보다 점수를 **올린다**"였다.
**그 반박은 이 새 제안에는 통하지 않는다.** 가중치 비례(`x(1 - 빠진축_가중치합)`)는
큰 축이 빠지면 지금보다 **더** 깎는다. 지적은 맞다.

ChatGPT 2차 #1 은 조건을 달았다: "검증 결과가 충분하지 않으면 공식을 변경하지 않는다."
옳은 조건이다. 그래서 **운영 데이터로 먼저 쟀다**
(`scripts/sensitivity_missing_axis.py`, 106종).

```
결측이 있는 종목: 79 / 106 (75%)
어떤 축이 빠지나: value 75, quality 11, sentiment 7
  US · quality    결측   4 /  31 ( 13%)
  KR · value      결측  75 /  75 (100%)   ← 🟥
  KR · quality    결측   7 /  75 (  9%)
  KR · sentiment  결측   7 /  75 (  9%)
대안이 더 낮게: 68종 · 더 높게: 0종 · 중앙 -7.30점

상위 15 명단
  현행: NVDA PSX EOG VLO CVX MPC 005930 036570 XOM COP 000660 MSFT ADBE OXY 329180
  대안: NVDA PSX EOG VLO CVX MPC XOM COP MSFT ADBE OXY AVGO CRM META CSCO
  빠짐: 005930 036570 000660 329180   ← 전부 한국
  들어옴: AVGO CRM META CSCO          ← 전부 미국
```

### 숫자가 말한 것은 공식 이야기가 아니었다

**KR 가치 축 결측률 100%.** 75종 중 75종. 미국은 0%.

100% 는 '데이터 부족'이 아니다. **수집 고장**이다.
확인해 보니 `_kr_fundamentals` 가 네이버 PC 종목 페이지의 `_per`/`_pbr`/`_eps`/
`_cns_per` ID 를 긁고 있었는데, **네이버가 그 페이지를 클라이언트 렌더링으로
바꾸면서 ID 가 전부 사라졌다.** 함수는 설계대로 조용히 `{}` 를 반환했다 —
주석에도 "HTML 구조 변경 시 빈 dict 반환"이라고 적혀 있다. 의도된 동작이었다.

그래서 **아무 에러도 안 났다.** 결측 감점(x완성도/5)이 점수를 그럴듯하게 만들었고,
화면에는 '데이터 없음' 한 줄만 떴다. **두 장치가 고장을 정상처럼 보이게 했다.**

> 만약 Gemini 의 처방을 **재 보지 않고** 받았다면, 한국 종목 전체에
> x0.80 대신 x0.65 를 곱했을 것이다. 데이터 파이프가 끊긴 것을
> **"한국 주식은 원래 점수가 낮다"로 굳히는** 결과가 됐다.

### 그래서 한 일

| | |
|---|---|
| 1 | `_kr_fundamentals` 를 네이버 **모바일 JSON API** 로 교체 (`m.stock.naver.com/api/stock/{code}/integration`). PER·추정PER·EPS·PBR·배당수익률·시총을 전부 준다 — 옛 HTML 보다 값이 많고 구조가 안정적이다. |
| 2 | **감지기 신설** `test_kr_value_axis.py` — 🟥 **한 시장의 한 축이 100% 비면 실패.** 개별 종목이 비는 것은 정상, 전부 비는 것은 비정상. 이 한 줄이 같은 사고를 잡는다. |
| 3 | 실패 메시지에 **스캔 시점**과 **다음 행동**을 넣었다. 수집을 고친 직후에는 운영 데이터가 아직 옛 스캔이라 실패하는데, "고장났다"고만 적혀 있으면 고친 사람이 자기 수정을 의심한다. |

### 공식은 **아직 바꾸지 않는다**

가중치 비례 자체는 맞는 방향이다. 다만 **지금 재면 결과가 오염돼 있다** —
KR 가치 결측 100% 상태에서 잰 민감도는 공식의 성질이 아니라 고장의 그림자다.
재스캔으로 가치 축이 채워진 뒤 **다시 재고 그때 결정한다.**
ChatGPT 가 건 조건("검증이 충분하지 않으면 바꾸지 않는다")을 그대로 지킨다.

## §1. 레이더 면적 왜곡 — **Gemini 가 맞고 내가 틀렸다**

1차에서 나는 "축 순서가 `AXES` 상수로 고정이므로 종목 간 비교에서 면적 왜곡이
없다"고 했다. **기하학적으로 오류다.**

정n각형 레이더의 면적은 `A = ½·sin(2π/n)·Σ(Sᵢ × Sᵢ₊₁)` — **이웃한 축끼리의 곱**의
합이다. 축 순서가 모든 종목에서 같아도, 높은 점수가 **서로 붙어 있는** 종목은
흩어져 있는 종목보다 면적이 크다. 총점이 같아도 그렇다.

- 90·90 인접 → 8100
- 90·10·90 → 900 + 900 = 1800

같은 두 90점인데 면적이 4.5배 차이 난다. 순서 고정은 이 이웃 효과를 없애지 못한다.

**정정한다.** 다행히 1차에서 넣은 축별 가로 막대(`AxisBars`)가 기여도·결측을
숫자로 담당하므로 화면상 피해는 막혀 있다. 레이더는 '모양'만 본다는 전제로 남긴다.

## §2. 수용 — 축별 기여도 합 검증 (ChatGPT 2차 #2)

상세 화면이 축마다 "종합에 +n.n" 을 찍는다. 그 합이 종합점수와 다르면 사용자는
**검산할 수 없는 숫자**를 보게 된다. 프런트와 백엔드가 같은 식을 **각자** 구현하고
있어서 언젠가 갈라진다 — 갈라져도 둘 다 그럴듯한 숫자라 화면에서 티가 안 난다.

→ 불변식으로 묶었다 (`test_axis_contributions_sum_to_the_composite_score`,
`test_contribution_formula_matches_the_frontend`).

```
contrib_i = (w_i × v_i / den) × (완성도/5)
Σ contrib = base × factor = composite_score
```

## §4. 이번 라운드에서 배운 것

**외부 검증의 값어치는 '처방'이 아니라 '재 보게 만드는 질문'에 있다.**

1차에 내가 쓴 교훈은 "현상 지적은 정확, 원인 진단은 거의 틀림"이었다.
이번에도 그 구조가 반복됐다 — Gemini 의 **처방**(가중치 비례 공식)을 그대로
받았으면 한국 주식을 체계적으로 깎았을 것이다. 그런데 그 처방을 **검증하려고
숫자를 재는 과정**에서 진짜 고장(KR 가치 결측 100%)이 나왔다.

> 지적을 받으면 처방을 보지 말고 **그 지적이 참이려면 데이터가 어떤 모양이어야
> 하는지**를 재라. 모양이 예상과 다르면, 거기에 진짜 문제가 있다.

그리고 Perplexity 의 자기 정정("제 식은 현행보다 점수를 올리는 처방이 맞습니다",
"인용 마커 `[^17]` 는 제 검토 환경 내부 식별자라 다온 문서에 존재하지 않습니다")은
검증자로서 신뢰를 높인다. 다음 검증 요청에는 **파일명·섹션·원문 문장·코드 라인**을
같이 내보내기로 한 합의를 지킨다.
