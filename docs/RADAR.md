### 안에서 본 것 — 밀도를 늘린 것은 나다

오늘 하루 내가 추가한 화면 두 개를 토스 기준으로 다시 읽었다.
- **중기 국면 카드**: 각주가 두 줄이다. "현재가가 200일선 위/아래 × 200일선이 최근
  60일간 올랐는가/아니는가 — 네 칸으로 나눈 것일 뿐…" + "종가(배당 미조정) — 수익률은
  가격 기준이다…". **규약을 지키려다 각주가 본문보다 길어졌다.**
- **지수 알림 패널**: 12행 × (라벨·±·입력칸·%·토글). 한 화면에 들어가지만 **읽히지는 않는다.**

**채택 (3건)**

- **① 잡초 뽑기 — 화면 문구를 한 번에 훑어 줄인다** — [토스 '잡초 뽑기'](https://ditoday.com/%ed%86%a0%ec%8a%a4-10%eb%85%84-%ec%89%ac%ec%9a%b4-%ea%b8%88%ec%9c%b5%ec%9d%b4-%eb%a7%8c%eb%93%a0-%ed%98%81%ec%8b%a0%ea%b3%bc-%ea%b7%b8%eb%8a%98/)
  - 바뀌는 곳: 설명문·각주가 있는 전 화면. 우선 `MidtermRegimeCard`·`NotificationsBell` 설정 패널·`AllocationTab` 안내문
  - 비용: 0원. 반나절
  - 로드맵: `화면 문구 잡초 뽑기` (검토 예정)
  - 왜: 다온의 설명문은 **정확하지만 길다.** R6(문장마다 줄바꿈)이 긴 산문을 오히려 허용하는 쪽으로 작동했다. 줄바꿈은 긴 글을 읽히게 하지, 짧게 만들지 않는다.
  - ⚠ 함정: **각주를 지우면 🟥 숫자 규약(기준·분모를 값과 함께 준다)을 깬다.** 지우지 말고 **접는다** — 한 줄 요약 + `InfoTip`(이미 있는 컴포넌트)으로 전문을 넣는다. 정보는 그대로 두고 **첫 화면에서만 덜어낸다.**

- **② 전문용어는 일상어를 앞에, 전문어를 괄호로** — [토스: 전문 용어 축소](https://ditoday.com/%ed%86%a0%ec%8a%a4-10%eb%85%84-%ec%89%ac%ec%9a%b4-%ea%b8%88%ec%9c%b5%ec%9d%b4-%eb%a7%8c%eb%93%a0-%ed%98%81%ec%8b%a0%ea%b3%bc-%ea%b7%b8%eb%8a%98/)
  - 바뀌는 곳: `_concentration`·`_currency_exposure` 가 그리는 카드, `MidtermRegimeCard`, AI 리포트 라벨
  - 비용: 0원. 반나절
  - 로드맵: `전문용어 일상어 병기` (검토 예정)
  - 왜: 화면에 `HHI`·`유효 종목 수`·`MDD`·`샤프`·`이격도`가 그대로 떠 있다. "200일선 -5.02%" 보다 "200일선보다 5% 아래"가 읽힌다.
  - ⚠ 함정: **지우지 말고 병기한다.** 오너는 전문 사용자다 — 전문어를 없애면 정보가 준다. 그리고 토스의 '외상' 사고가 보여주듯 **쉬운 말로 바꾸다 위험을 작게 보이게 하면 그건 개선이 아니다.** '추세 이탈'을 '조정 중' 같은 부드러운 말로 바꾸지 않는다.

- **③ 분석 탭 — 한 번에 한 장만** — 토스의 '한 화면 한 기능' (⚠ 이 원칙은 Q&A 답변 출처라 근거가 약하다. 아래 수치와 달리 **주장으로만 취급**한다)
  - 바뀌는 곳: `AllocationTab` 의 Ⅰ·Ⅱ·Ⅲ·부록을 세그먼트로 갈라 한 장씩
  - 비용: 0원. 1~2 세션
  - 로드맵: `분석 탭 한 번에 한 장` (검토 예정)
  - 왜: 지금 네 장이 한 스크롤에 있다. 오늘 중기 국면 카드까지 Ⅰ장에 들어가 더 길어졌다.
  - ⚠ **오너 확인 필수**: 2026-10-30 에 오너 요청으로 **틀고정 목차(ChapterNav)를 지웠다.** 세그먼트는 목차와 다르지만 "또 네비게이션" 으로 보일 수 있다. **제안만 하고 착수는 오너 결정.** 반대라면 대안은 ③′ — 장을 가르지 말고 **Ⅰ장을 짧게**(중기 국면 카드를 Ⅱ장으로 옮기거나 접기).

**기각 / 보류**

- **구어체(해요체) 전면 전환** — 다온은 "~합니다"로 통일돼 있고, 섞이면 더 산만하다. 말투보다 **길이**가 문제다(①이 먼저). **다시 볼 조건: ① 적용 후에도 읽기 어려울 때.**
- **하단 고정 주문 버튼(토스 패턴)** — 다온에 매매 기능이 없다(오너 선). **다시 볼 조건: 없음.**
- **탭 수 줄이기(10개 → 4~5개)** — 효과는 가장 클 수 있으나 전 화면 재배치다. UI 레인 상한 3건에 걸려 미뤘다. **다시 볼 조건: 다음 주 1순위 후보.**
- **UX 스코어 기반 기능 베끼기** — 리포트는 **점수만** 주고 차원별 원인을 주지 않는다. 원인을 모르는 점수에서 기능을 역추론하면 그건 벤치마킹이 아니라 추측이다. **다시 볼 조건: 유료 리포트 전문을 보게 될 때.**

추렸다. 매매 기능은 조사 대상에서 뺐다(오너 선).

**출처 규약** — 기능 목록은 **공식 리포 README 만** 인용했다. 1차 검색이 데려온
디렉터리·호스팅 업체 페이지(selfhostyourself·hostinger·sourceforge 류)는 기능이
README 와 달랐다. 한 곳은 Ghostfolio 에 'X-ray 규칙 엔진'이 있다고 적었는데 README 에는
그런 이름이 없다. **벤더·중개 페이지의 기능 주장은 인용하지 않는다.**

### 한 줄 결론 — 비교해 보니 다온이 앞선 쪽이 더 많았다

**세 앱 중 알림을 가진 앱이 하나도 없다.** 셋 다 README 에 notification/alert 가 없다.
다온의 목표가·손절가·급등락·실적발표·지수 알림 + Web Push 는 이 범주에서 독보적이다.
Ghostfolio 의 '정적 위험 분석'도 다온이 이미 더 깊다 — 룰 엔진(`ticker_concentration`·
`sector_concentration`) + HHI·유효 종목 수 + 기초자산 기준 환노출 + 그 위의 AI 진단.

**셋 다 가졌는데 다온에 없는 것은 사실상 하나다 — 벤치마크 대비 성과.**
그리고 다온은 이미 그걸 알고 있다:

```python
METRICS_BASIS = { 'return_basis': '평균단가 대비 (시장 벤치마크 대비가 아님)',
                  'benchmark': None }   # 없다. 없는 것을 있다고 적지 않는다.
```

"내 수익률 12%"는 같은 기간 지수가 18% 올랐으면 **진 것**이다. 지금 다온은 그 질문에
답할 수 없다. 채택 3건 중 둘이 여기에 몰린 이유다.

**채택 (3건)**

- **① 지수 대비 상대성과 — 가격 기반, 입출금 이력 없이 지금 가능** — [Wealthfolio README](https://github.com/afadil/wealthfolio) 'benchmark comparison'
  - 바뀌는 곳: 분석 탭 성과 카드 · `METRICS_BASIS['benchmark']` 를 `None` → 실제 값 · 보유 종목별 `(종목 수익률 − 지수 수익률)`
  - 비용: 0원 — 지수 가격은 `_market_data`·`_yf_chart` 로 이미 받고 있다. 반나절(추정)
  - 로드맵: `지수 대비 상대성과` (검토 예정)
  - 왜: **보유 기간이 아니라 가격 구간**으로 재면 현금 흐름이 필요 없다. KR 종목은 KOSPI, US 는 S&P500 을 짝지어 같은 창으로 비교한다. 지금 당장 할 수 있는 유일한 정직한 벤치마크다.
  - ⚠ 함정: 매수 전 구간을 섞으면 거짓이 된다. **최초 매수일 이후만** 쓴다(드로다운 카드와 같은 규칙).

- **② 입출금(현금 흐름) 기록 → TWR·MWR** — [Wealthfolio README](https://github.com/afadil/wealthfolio) 'true time-weighted and money-weighted returns'
  - 바뀌는 곳: 새 테이블 `cash_flows`(입금·출금·일자) · `net_worth_snapshots` 해석 · 자산 추이 카드
  - 비용: 0원(외부 호출 없음). 1~2일(추정) — **입력 UI 가 일의 절반이다**
  - 로드맵: `입출금 기록 → TWR·MWR` (검토 예정)
  - 왜: **지금 다온의 자산 추이는 "성과"와 "저축"을 구분하지 못한다.** `transactions` 는 BUY/SELL 만 적고(스키마 확인함) 입금 행이 없어서, 월급을 넣으면 그래프가 오르고 그건 수익처럼 보인다. 🟥 숫자 규약 1번("이름이 거짓말을 하면 아무도 의심하지 않는다") 그대로의 자리다.
  - ⚠ 이것이 ①보다 큰일인 이유: 포트폴리오 **전체** TWR 은 흐름 없이는 계산이 불가능하다. 추정해서 채우면 없는 사실을 지어내는 것이다(🟥 숫자 규약 3번). 그래서 ①을 먼저, ②를 나중에 둔다.

- **③ 로컬 MCP 서버 — Claude 가 다온을 직접 읽는다** — [Ghostfolio README](https://github.com/ghostfolio/ghostfolio) 'experimental Model Context Protocol (MCP) server'
  - 바뀌는 곳: `backend/` 에 MCP 엔드포인트 1벌(읽기 전용) · 기존 `require_approved` 재사용
  - 비용: 0원. 1일(추정)
  - 로드맵: `로컬 MCP 서버(읽기 전용)` (검토 예정)
  - 왜: 오너는 Claude 를 매일 쓴다. 지금은 다온 데이터를 보려면 화면을 열어 눈으로 읽고 옮겨 적는다. MCP 면 "내 반도체 비중 얼마야"를 대화에서 바로 묻는다.
  - ⚠ 전제: **읽기 전용 + 자기 서버에서만.** 쓰기를 열면 알림·보유가 대화 한 줄로 바뀐다. 🟥 개인 데이터 격리 규약을 그대로 적용한다 — 공유 캐시 경로를 타지 않게 할 것.

**기각 / 보류**

- **Ghostfolio 정적 위험 분석(X-ray 류)** — 다온이 이미 더 깊다(룰 엔진 + HHI·유효 종목 수 + 기초자산 환노출 + AI 진단). **다시 볼 조건: 없음.**
- **Wealthfolio 애드온 SDK(TypeScript·권한 시스템)** — 사용자가 사실상 1명인 앱에 플러그인 생태계는 비용만 늘린다. **다시 볼 조건: 다온을 남에게 열 때.**
- **목표 관리(Goal Planning)** — 이미 있다(`/api/goals` + 몬테카를로 투영). **다시 볼 조건: 없음.**
- **rotki PnL 회계 리포트** — FIFO 실현손익이 이미 있고 테스트로 고정돼 있다. 다만 rotki 는 **회계 설정을 사용자가 바꾼다**(선입선출 외 선택). 한국 세법은 FIFO 고정이라 의미가 없다. **다시 볼 조건: 없음.**
- **Zen Mode / Dark Mode** — 가림(privacy) 모드와 테마가 같은 일을 한다. **다시 볼 조건: 없음.**
- **증권사 자동 동기화(Wealthfolio Connect, 30여 곳 읽기전용)** — 오너는 파일 임포트로 쓰고 있고, 그 파서는 실파일 2벌로 고정돼 있다. **국내 증권사 포함 여부는 확인하지 못했다. 다시 볼 조건: 포함 목록을 확인했고 키움이 있을 때.**
- **데스크톱 네이티브(Tauri/Rust)** — PWA 가 폰·PC 를 이미 겸한다. 네이티브로 가면 배포 경로가 둘이 된다. **다시 볼 조건: 없음.**
