## 2026-11-01 — 증권사 계좌 연동, 다온도 되나 (오너 질문)

**먼저 두 가지를 갈라야 한다. 같은 말로 불리지만 다른 물건이다.**

### ① 토스·뱅크샐러드식 "여러 증권사 한 번에" = 마이데이터 → **다온은 불가**
금융위 허가 사업(본인신용정보관리업)이다.
- 자본금 **5억원**(신용정보법 제6조), 예비허가+본허가 **최소 3개월**, 보안설비·대주주
  적격성 등 6요건 ([금융위 관련 정리](https://dealsite.co.kr/articles/70338))
- **허가 없이 영업하면 5년 이하 징역 또는 5천만원 이하 벌금.**
- → 검토할 것이 없다. **기각, 다시 볼 조건 없음.**
⚠ 출처가 2020~21년 자료 위주다. 수치는 참고용이고, 실제로 추진할 일이 생기면
   국가법령정보센터 원문으로 다시 확인할 것. **다만 결론(개인 불가)은 바뀌지 않는다.**

### ② 본인 계좌를 본인 API 키로 = **가능하다**
| 증권사 | 개인 신청 | 확인된 제약 |
|---|---|---|
| [한국투자 KIS Developers](https://apiportal.koreainvestment.com/provider) | 가능 | **제3자 서비스 제공 목적이면 별도 제휴 필요**(자사 법인 계좌 이용은 제휴 불요) |
| [키움 REST API](https://www.smarttoday.co.kr/ko-kr/articles/83887) | 가능 | **본인 서버 IP 등록 필수 · 토큰은 그 IP 에서만 유효 · 24시간 만료 · 초당 20회**(IP·토큰·횟수는 비공식 라이브러리 문서 기준) |
| 미래에셋 | **확인 못 했다** | 검색으로 공식 자료를 찾지 못했다. 없다고 적지 않는다 |

오너 주력은 키움·미래에셋이다. 키움이 **IP 를 고정**시키는 것은 다온 구조와 맞는다 —
Oracle 인스턴스가 고정 IP(168.107.13.20)를 갖고 있다.

### 리스크 — 기술보다 이쪽이 크다
1. **사용자가 2명이라는 것.** 내 계좌를 내 키로 보는 건 괜찮지만, **남의 계좌를
   다온이 대신 조회하면 '제3자 서비스'** 가 되어 제휴 대상이 된다. 1인용일 때와
   2인용일 때 답이 다르다. 연동을 붙인다면 **오너 계정 전용 기능**이어야 한다.
2. **키가 곧 계좌다.** 증권사 API 키는 조회만이 아니라 **주문 권한을 포함**한다.
   서버에 키를 두는 순간, 서버가 뚫리면 조회가 아니라 **매매가 뚫린다.**
   지금 다온 서버는 개인이 운영하는 Oracle 무료 인스턴스다.
   → **해법은 이미 다온 안에 있다.** 종목분석이 쓰는 **오너 PC 스케줄러**에 API 를
   붙이고, 서버에는 **결과만** 올린다. 키가 공개 서버에 존재하지 않는다.
3. **조용히 멈추는 고장이 둘 는다.** IP 가 바뀌면(인스턴스 재생성) 토큰이 죽고,
   24시간 토큰 갱신이 실패해도 죽는다. 둘 다 화면에는 아무 일도 안 일어난다 —
   다온이 이미 당한 종류다(주간 종합 3주 정지·일일 분석 17%).
   신선도 점검을 **기능과 같이** 넣어야 한다.
4. **얻는 것이 생각보다 적다.** 오너는 이미 엑셀 업로드로 한 번에 갱신한다.
   API 가 더해 주는 것은 ①업로드를 안 해도 됨 ②**예수금 자동 갱신** 둘인데,
   진짜 이득은 ②다 — 2026-10-31 에 확인한 "파일 4개 중 1개만 현금 줄이 있다"
   문제를 정확히 푼다.

**보류 (오너 결정 대기)**
- **키움 REST API 조회 전용 연동(오너 계정·PC 경유)** — 위 구조로 한정하면 리스크가
  관리 가능하다. 다만 **지금 당장의 이득은 예수금 자동화 하나**이므로 우선순위는 높지 않다.
  로드맵에 올리고 착수는 오너 결정.
- **마이데이터 연동** — 기각. 다시 볼 조건 없음.
- **스크래핑(아이디·비밀번호 대행 로그인)** — 기각. 약관 위반이고 자격증명을 쥐게 된다.
  **다시 볼 조건: 없음.**

## 2026-10-31 (2) — UI 레인 개설: "토스증권처럼 쉽고 깔끔하게"

오너 상시 지시로 **UI 레인을 상시 1순위**로 열었다(`SKILL.md` 2단계). 첫 라운드.

### 바깥에서 가져온 것

**토스의 쉬운 말 원칙** ([DI Today, 토스 10년](https://ditoday.com/%ed%86%a0%ec%8a%a4-10%eb%85%84-%ec%89%ac%ec%9a%b4-%ea%b8%88%ec%9c%b5%ec%9d%b4-%eb%a7%8c%eb%93%a0-%ed%98%81%ec%8b%a0%ea%b3%bc-%ea%b7%b8%eb%8a%98/))
- **잡초 뽑기** — 의미에 영향 없는 단어를 걷어낸다. "앞으로 받을 배당금" → "받을 배당금".
- 전문 용어를 줄이고 구어체(해요체)를 쓴다.

**사용자 평가 수치** ([오픈서베이 금융 앱 UX 리포트 2024](https://blog.opensurvey.co.kr/article/ux-finance-app-3/), 1,000명·앱당 200명)

- Offering: 토스 67.6 / 평균 58.6 / 영웅문 56.8.
- ⚠ 차원별 세부 이유는 리포트 요약에 없다. **점수만 인용하고 원인은 추측하지 않는다.**

**단순화의 선** — 토스는 '미수거래'를 '외상'으로 바꿨다가 금감원 시정명령으로
2024년 1월 되돌렸다. FCA 2022 연구도 과도한 단순화·게이미피케이션 경고.
→ **쉬운 단어와 작아 보이는 위험은 다르다.** 다온의 "판정하지 않고 숫자만"이 이 선이다.

### 안에서 본 것 — 밀도를 늘린 것은 나다

오늘 하루 내가 추가한 화면 두 개를 토스 기준으로 다시 읽었다.
- **중기 국면 카드**: 각주가 두 줄이다. "현재가가 200일선 위/아래 × 200일선이 최근
  60일간 올랐는가/아니는가 — 네 칸으로 나눈 것일 뿐…" + "종가(배당 미조정) — 수익률은
  가격 기준이다…". **규약을 지키려다 각주가 본문보다 길어졌다.**
- **지수 알림 패널**: 12행 × (라벨·±·입력칸·%·토글). 한 화면에 들어가지만 **읽히지는 않는다.**

**채택 (3건)**

- **① 잡초 뽑기 — 화면 문구를 한 번에 훑어 줄인다** — [토스 '잡초 뽑기'](https://ditoday.com/%ed%86%a0%ec%8a%a4-10%eb%85%84-%ec%89%ac%ec%9a%b4-%ea%b8%88%ec%9c%b5%ec%9d%b4-%eb%a7%8c%eb%93%a0-%ed%98%81%ec%8b%a0%ea%b3%bc-%ea%b7%b8%eb%8a%98/)
  - 바뀌는 곳: 설명문·각주가 있는 전 화면. 우선 `MidtermRegimeCard`·`NotificationsBell` 설정 패널·`AllocationTab` 안내문
  - 비용: 0원. 반나절
  - 로드맵: `화면 문구 잡초 뽑기` (검토 예정)
  - 왜: 다온의 설명문은 **정확하지만 길다.** R6(문장마다 줄바꿈)이 긴 산문을 오히려 허용하는 쪽으로 작동했다. 줄바꿈은 긴 글을 읽히게 하지, 짧게 만들지 않는다.
  - ⚠ 함정: **각주를 지우면 🟥 숫자 규약(기준·분모를 값과 함께 준다)을 깬다.** 지우지 말고 **접는다** — 한 줄 요약 + `InfoTip`(이미 있는 컴포넌트)으로 전문을 넣는다. 정보는 그대로 두고 **첫 화면에서만 덜어낸다.**

- **② 전문용어는 일상어를 앞에, 전문어를 괄호로** — [토스: 전문 용어 축소](https://ditoday.com/%ed%86%a0%ec%8a%a4-10%eb%85%84-%ec%89%ac%ec%9a%b4-%ea%b8%88%ec%9c%b5%ec%9d%b4-%eb%a7%8c%eb%93%a0-%ed%98%81%ec%8b%a0%ea%b3%bc-%ea%b7%b8%eb%8a%98/)
  - 바뀌는 곳: `_concentration`·`_currency_exposure` 가 그리는 카드, `MidtermRegimeCard`, AI 리포트 라벨
  - 비용: 0원. 반나절
  - 로드맵: `전문용어 일상어 병기` (검토 예정)
  - 왜: 화면에 `HHI`·`유효 종목 수`·`MDD`·`샤프`·`이격도`가 그대로 떠 있다. "200일선 -5.02%" 보다 "200일선보다 5% 아래"가 읽힌다.
  - ⚠ 함정: **지우지 말고 병기한다.** 오너는 전문 사용자다 — 전문어를 없애면 정보가 준다. 그리고 토스의 '외상' 사고가 보여주듯 **쉬운 말로 바꾸다 위험을 작게 보이게 하면 그건 개선이 아니다.** '추세 이탈'을 '조정 중' 같은 부드러운 말로 바꾸지 않는다.

- **③ 분석 탭 — 한 번에 한 장만** — 토스의 '한 화면 한 기능' (⚠ 이 원칙은 Q&A 답변 출처라 근거가 약하다. 아래 수치와 달리 **주장으로만 취급**한다)
  - 바뀌는 곳: `AllocationTab` 의 Ⅰ·Ⅱ·Ⅲ·부록을 세그먼트로 갈라 한 장씩
  - 비용: 0원. 1~2 세션
  - 로드맵: `분석 탭 한 번에 한 장` (검토 예정)
  - 왜: 지금 네 장이 한 스크롤에 있다. 오늘 중기 국면 카드까지 Ⅰ장에 들어가 더 길어졌다.
  - ⚠ **오너 확인 필수**: 2026-10-30 에 오너 요청으로 **틀고정 목차(ChapterNav)를 지웠다.** 세그먼트는 목차와 다르지만 "또 네비게이션" 으로 보일 수 있다. **제안만 하고 착수는 오너 결정.** 반대라면 대안은 ③′ — 장을 가르지 말고 **Ⅰ장을 짧게**(중기 국면 카드를 Ⅱ장으로 옮기거나 접기).

**기각 / 보류**

- **구어체(해요체) 전면 전환** — 다온은 "~합니다"로 통일돼 있고, 섞이면 더 산만하다. 말투보다 **길이**가 문제다(①이 먼저). **다시 볼 조건: ① 적용 후에도 읽기 어려울 때.**
- **하단 고정 주문 버튼(토스 패턴)** — 다온에 매매 기능이 없다(오너 선). **다시 볼 조건: 없음.**
- **탭 수 줄이기(10개 → 4~5개)** — 효과는 가장 클 수 있으나 전 화면 재배치다. UI 레인 상한 3건에 걸려 미뤘다. **다시 볼 조건: 다음 주 1순위 후보.**
- **UX 스코어 기반 기능 베끼기** — 리포트는 **점수만** 주고 차원별 원인을 주지 않는다. 원인을 모르는 점수에서 기능을 역추론하면 그건 벤치마킹이 아니라 추측이다. **다시 볼 조건: 유료 리포트 전문을 보게 될 때.**

## 2026-10-31 (오픈소스 포트폴리오 앱 벤치마킹 — 오너 요청 #9)

정규 주차가 아니라 **오너 지정 조사**다. GitHub 공개 앱을 훑어 다온에 없는 UI/UX·기능을
추렸다. 매매 기능은 조사 대상에서 뺐다(오너 선).

**출처 규약** — 기능 목록은 **공식 리포 README 만** 인용했다. 1차 검색이 데려온
디렉터리·호스팅 업체 페이지(selfhostyourself·hostinger·sourceforge 류)는 기능이
README 와 달랐다. 한 곳은 Ghostfolio 에 'X-ray 규칙 엔진'이 있다고 적었는데 README 에는
그런 이름이 없다. **벤더·중개 페이지의 기능 주장은 인용하지 않는다.**

### 한 줄 결론 — 비교해 보니 다온이 앞선 쪽이 더 많았다

**세 앱 중 알림을 가진 앱이 하나도 없다.** 셋 다 README 에 notification/alert 가 없다.
다온의 목표가·손절가·급등락·실적발표·지수 알림 + Web Push 는 이 범주에서 독보적이다.
Ghostfolio 의 '정적 위험 분석'도 다온이 이미 더 깊다 — 룰 엔진(`ticker_concentration`·
`sector_concentration`) + HHI·유효 종목 수 + 기초자산 기준 환노출 + 그 위의 AI 진단.

**셋 다 가졌는데 다온에 없는 것은 사실상 하나다 — 벤치마크 대비 성과.**
그리고 다온은 이미 그걸 알고 있다:

```python
METRICS_BASIS = { 'return_basis': '평균단가 대비 (시장 벤치마크 대비가 아님)',
                  'benchmark': None }   # 없다. 없는 것을 있다고 적지 않는다.
```

"내 수익률 12%"는 같은 기간 지수가 18% 올랐으면 **진 것**이다. 지금 다온은 그 질문에
답할 수 없다. 채택 3건 중 둘이 여기에 몰린 이유다.

**채택 (3건)**

→ 실패 메시지에 스캔 시점과 다음 행동을 넣었다 — 수집을 고친 직후엔 운영
   데이터가 옛 스캔이라 실패하는데, "고장났다"고만 적으면 자기 수정을 의심하게 된다.

> **교훈:** 지적을 받으면 처방을 보지 말고, **그 지적이 참이려면 데이터가 어떤
> 모양이어야 하는지**를 재라. 모양이 예상과 다르면 거기에 진짜 문제가 있다.
> 처방을 그대로 받았으면 한국 주식에 ×0.65 를 곱해, 끊어진 파이프를
> "한국 주식은 원래 점수가 낮다"로 굳혔을 것이다.

**정정 — 내가 틀렸던 것**

- **레이더 면적 왜곡**: 1차에서 "축 순서가 고정이면 왜곡 없음"이라고 반박했다.
  **기하학적 오류다.** 면적 = ½·sin(2π/n)·Σ(Sᵢ×Sᵢ₊₁) — 이웃 축끼리의 곱이라,
  순서가 같아도 **높은 점수가 붙어 있는 종목이 더 커 보인다**(90·90=8100 vs
  90·10·90=1800). Gemini 2차가 맞다. 화면 피해는 `AxisBars` 가 이미 막고 있다.
- **1차 반박의 사정거리**: "제안들은 전부 지금보다 후하다"는 반박은 **가중치 비례
  제안에는 통하지 않는다**(큰 축이 빠지면 더 깎는다). 반박에도 유효범위가 있다.
