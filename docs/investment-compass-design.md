# 투자 나침반 — 설계안 비교 (오너 승인 대기)

> 오너 의도: "유튜브에 매일 쏟아지는 AI 기술동향·거시경제·빅테크 방향을 총망라해
> 앱에서 핵심 메시지·투자 기사를 제안. 투자를 놀이처럼 느끼며 학습 → 실제 투자 → 자산 증식."
> 합격 기준(핸드오프 명시): **"내 포트폴리오에 무슨 의미인지까지 이어져야 '나침반'이다."**

## 0. 조사에서 나온 사실 (설계를 바꾸는 것들)

1. **기존 `/api/youtube/analyze`는 자막을 안 읽는다.** 입력이 `video_id·title·channel`
   뿐이고, 프롬프트는 **제목과 채널명만** 보고 "언급된 종목·투자 시사점"을 만든다.
   → 지금 이 엔드포인트를 그대로 확장하면 **구조적 환각 생성기**가 된다. 재사용 대상이 아니라
   **교체 대상**이다.
2. **자막은 공식 경로로 못 받는다.** YouTube Data API v3 는 메타데이터만 준다.
   `captions.download` 는 **영상 소유자만** 호출 가능. 비공식 스크래핑 라이브러리는
   차단·ToS 리스크를 진다.
3. **`knowledge/tech-radar` 는 아직 비어 있다**(디렉토리 없음). 재사용할 축적물이 없다.
   반면 **`knowledge/daily-briefing` 은 실재**하고, 웹검색 6축 요약이라는 형식이
   이 기능과 사실상 같은 모양이다 — 이쪽이 실질적 선례다.
4. **오늘(2026-08-18) 만든 일 1회 분석 갱신 배치**가 이미 매일 보유 종목에 대해
   web_search 를 돌린다. 나침반의 데이터 수집 절반이 이미 굴러가고 있다.

## 1. 설계안 비교

| | **안 A — 보유 연동 "오늘의 한 줄"** | **안 B — 매크로 나침반 탭** | **안 C — 유튜브 구독형 (원안)** |
|---|---|---|---|
| **한 줄** | 매일 갱신되는 내 종목 분석에서 "그래서 내 포트폴리오엔?"을 뽑아 홈 배너로 | 일 1회 거시·AI·빅테크 웹검색 요약 + 내 보유와의 연결을 탭으로 | 오너 지정 채널의 신규 영상을 요약해 종목과 연결 |
| **데이터 소스** | 이미 도는 종목 분석(web_search 뉴스·실적) | web_search (daily-briefing 6축 방식) | YouTube 메타데이터 + **자막** |
| **추가 AI 비용** | **거의 0** — 기존 배치 프롬프트에 필드 1개 추가 | 검색 8회/일 + 토큰 ≈ **월 $3~5** | 자막은 길다. 5영상/일이면 **월 $20~40** |
| **환각·클릭베이트 내성** | **높음** — 기존 분석의 출처 표기·"확인 필요" 규율을 그대로 상속 | 중상 — 검색 출처 있음, 도메인 화이트리스트로 통제 가능 | **낮음** — 유튜버 개인 의견이 원천. 썸네일 낚시가 구조적으로 섞임 |
| **"내 포트폴리오 의미" 연결** | **구조적으로 보장** (보유 종목에서 출발) | 사후 연결 — 프롬프트로 유도해야 함 | 사후 연결 — 영상이 내 종목을 다룰 보장이 없음 |
| **거시·기술동향 커버** | **약함** (개별 종목 중심) | **강함** | 강함(채널 선택에 좌우) |
| **기술·법적 리스크** | 없음 | 없음 | **자막 수집 수단이 불안정**(비공식 API 차단·ToS) |
| **구현 규모** | 반나절 | 2~3일 | 1주+ (수집 인프라부터) |
| **정보 과부하** | 낮음 (1일 1문단) | 중 — 하루 3건 상한 필요 | 높음 — 영상 수만큼 늘어남 |

## 2. 권고

**A → B 순차. C 는 현 시점 비권장.**

근거:

- **C 는 세 축 모두 불리하다** — 비용 최고, 신뢰도 최저, 기술 리스크 유일. 오너 의도의
  원안이지만 "유튜브"는 **수단**이지 목적이 아니다. 목적("동향을 총망라해 내 투자에 연결")은
  A+B 로 더 싸고 더 정확하게 달성된다.
- **A 가 합격 기준을 유일하게 구조적으로 만족한다.** "내 포트폴리오에 무슨 의미인지"가
  사후 연결이 아니라 출발점이다. 그리고 **이미 도는 배치에 얹으므로 추가 비용이 사실상 0**이다.
- **B 는 A 가 못 채우는 거시·기술동향 축을 채운다.** A 로 형식과 반응을 확인한 뒤 붙이는
  게 순서상 맞다.

### 정보 과부하 방지 (오너가 논의 포인트로 지목한 것)
- **하루 1건 원칙.** A 는 문단 1개, B 는 최대 3건.
- **"읽음" 처리 후 사라짐** — ChangelogModal 이 쓰는 인앱 공지 패턴과 동일하게.
- 배너는 **접을 수 있게**. 놀이처럼 느끼려면 강제 노출이 아니라 선택 노출이어야 한다.

### 신뢰도 확보
- 모든 문장에 **출처 링크 필수**. 없으면 표시하지 않는다.
- 기존 종목 분석의 규율 그대로: 확인 안 된 항목은 `"확인 필요"`, 추측 금지.
- B 는 도메인 화이트리스트(로이터·블룸버그·연준·주요 IR)로 클릭베이트를 원천 차단.

## 3. 승인 필요 사항

1. **A 먼저 / B 먼저 / A+B 동시 / C 포함** 중 선택
2. B 채택 시 **6축 중 어떤 축**을 앱에 넣을지 (전부는 과부하)
3. C 를 굳이 원하면 — 자막 수집 수단의 ToS 리스크를 감수할지 오너 판단 필요

**승인 전까지 구현하지 않는다** (핸드오프 지시).
