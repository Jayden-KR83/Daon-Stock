## 1. 자가 테스트 — 실제로 돌려서 잰 것

### T1. 본문 최소 11px 로 올리면 화면이 깨지는가
`frontend/scripts/try-typography.mjs` — 360px 에서 계산된 글자 크기가 11px 미만인
요소를 **전부 11px 로 올린 뒤** 가로 넘침을 올리기 전과 비교했다(코드는 안 건드림).

```
폭 360px · 최소 글자 11px 로 올렸을 때
탭         올린요소  넘침(전→후)  최소글자(전→후)
포트폴리오     113   272 →  277  ⚠ +5   9 → 11
분석           102   203 →  203   =     9 → 11
관심            59   192 →  192   =     9 → 11
시장           118   220 →  221  ⚠ +1   6.5 → 9
```

**판정: 생각보다 안전하다.** 넘침이 **6곳** 늘 뿐이고 두 탭은 변화가 없다.
(기준값 192~272 는 가로 스크롤 컨테이너·흐르는 티커가 포함된 수라 절대값이 아니라
**증감**만 의미가 있다.)

**곁가지 발견 둘**
- 시장 탭은 11px 로 올려도 최소가 **9px 로 남는다** → 그 글자는 SVG 차트 안에 있다.
  **차트 축 라벨은 11px 규칙 대상이 아니다.** 축을 키우면 눈금이 겹친다.
- 가장 작은 글자가 **6.5px** 인 곳이 있었다(시장 탭 차트). 시안이 말한 9.5px 보다 작다.

### T2. 색 토큰을 바꾸면 몇 곳이 따라오나
```
--clr-bg          66곳
--clr-surface     79곳
--clr-border      67곳
--clr-text-strong 140곳
```
전부 `var(--토큰)` 참조다. **하드코딩 색이 아니라 토큰이므로 tokens.css 한 곳만 고치면 된다.**
→ 색 교체는 **저위험**. 단 다크·프로 테마에도 같은 축으로 값을 넣어야 한다
(`:root[data-theme='dark']` / `[data-theme='pro']` 가 원본 토큰을 덮는다).

### T3. 인라인 글자 크기 분포
```
843곳 (jsx 인라인 fontSize)
  11px  187   12px 137   10px 104   10.5px 77   13px 64   11.5px 54
   9px   50   12.5px 43  14px  31    9.5px 20   …  8px 9 · 8.5px 6 · 6.5px(SVG)
17단계
```
시안은 5단계를 요구한다. **843곳을 한 번에 고치는 것은 위험**하다 —
한 커밋에 전 화면이 바뀌면 깨진 곳을 찾을 수가 없다.

## 2. ⛔ 반영 불가 — 다온 원칙과 충돌

### 2-1. RSI "과매수 70 / 과매도 30"
시안 §3.4 가 이 단어를 쓴다. 그런데 다온은 **판정하지 않고 숫자를 준다**가 1원칙이고,
2026-11-02 커밋에 *"RSI 70/30 을 과매수·과매도라 단정하지 않는다"* 를 명시했다.
`indicators.py` 의 `INDICATOR_BASIS['note']` 가 그 문장을 담고 있고 테스트가 지킨다.

→ **기준선은 그대로 그리되 라벨은 숫자(70/30)만** 쓴다. 시안의 이 문구는 반영하지 않는다.
(토스가 '미수거래'를 '외상'으로 바꿨다 금감원 시정명령을 받은 것과 같은 선이다.
쉬운 말로 바꾸는 것과 판단을 대신 내려 주는 것은 다르다.)

### 2-2. "200일선 보라"
시안 §3.4 는 20 주황 / 60 초록 / **200 보라**라고 적었다. 그런데 **보라는 이미
120일선 색**(`#8B5CF6`)이고, 시안은 120일선을 아예 빠뜨렸다 — 한국 시장에서
120일선은 널리 쓰인다.
→ 현행 유지: 20 주황 · 60 초록 · 120 보라 · **200 회색**(배경 추세선).
추세선을 단기선보다 차분하게 두는 편이 읽기에도 낫다.

## 3. ⛔ 보류 — 오너의 이전 결정과 충돌

### 하단 내비 5탭 고정 (`포트폴리오·분석·종목·관심·더보기`)
시안 §3.1-B7 의 요구다. 그런데 **2026-10-31 에 오너가 이렇게 정했다**:

> "탭 10개를 절반 이하로 줄이는 건 **바로 고치는 게 위험한 것 같아**.
>  내가 다온을 사용했을 때 로그 기록을 관리자 모드에 구현해. … **그걸 기준으로
>  탭을 합쳐야 할 때 기준으로 삼겠어.**"

사용 로그는 **2026-11-01 배포로 막 쌓이기 시작했다(이틀치)**. 화면도 7일 미만이면
"아직 근거로 쓰기 이르다"고 스스로 말하도록 만들어 뒀다.

→ **지금 5탭으로 줄이면 오너가 세운 판단 절차를 건너뛴다.** 2~3주 뒤 체류시간을
보고 정하는 것이 원래 합의다. 시안은 그 사실을 모르고 쓰였다.
참고로 현재도 **'전체' 버튼**이 스크롤 밖에 고정돼 있어 '더보기'와 같은 역할을 한다.

## 4. ⚠ 설계가 더 필요한 것 — 분석 탭 4단 세그먼트

구조 자체는 옳다(한 번에 하나만 읽게 한다). 다만 지금 코드에는 숨은 의존이 있다.

- **AI 전략 분석 실행 버튼이 Ⅰ장 끝에 있다.** Ⅱ·Ⅲ·부록은 그 결과를 나눠 쓴다.
  탭으로 가르면 Ⅱ 탭에 들어간 사람은 *"AI 리스크 진단은 아직 없습니다"* 만 보고,
  버튼은 **다른 탭에** 있다. 길을 잃는다.
- 계좌 선택기는 **Ⅱ장 세그먼트와 Ⅰ장 드롭다운이 2026-11-02 에 하나로 합쳐졌다.**
  탭을 가르면 이 선택기를 어디에 둘지 다시 정해야 한다(모든 탭 공통 상단이 맞다).

→ 반영하려면 ① 실행 버튼을 **세그먼트 바 바로 아래 공통 영역**으로 올리고
② 계좌 선택기도 같은 자리에 두는 설계가 선행돼야 한다. 그림만 보고 자르면 안 된다.

## 5. ℹ 시안이 요구했지만 이미 충족된 것

| 시안 요구 | 현황 |
|---|---|
| 폰트 Manrope | `--font-sans: 'Manrope', …` — **이미 Manrope** |
| 가림 모드에서 % 유지 | `utils/privacy.js` 가 *"남긴다: 퍼센트(+12.3%)"* 로 이미 정의 |
| `tabular-nums` 로 흔들림 방지 | 금액 표시에 이미 광범위 적용 |
| 좌측 색띠 금지 · radius 4 · 1px 헤어라인 | design.md R1 로 이미 강제 |
| 매매 CTA 금지 | 다온에 매매 기능 자체가 없다 |

시안 §5 의 "클로드 코드 지시서"도 대부분 **이미 지켜지고 있는 규칙의 재진술**이다.
