# 시황 브리핑 비용 산정 · 자동화 계획 (2026-11-05)

오너 요청 두 가지에 대한 답이다.
1. "매일 거시 지표 기준으로 투자자가 취할 것 + 내 종목 참고사항을 시장 탭 최상단에.
   **API 소요 비용 산정**하고 미리 알려 달라."
2. "내가 매번 유튜브·블로그를 검색해서 개선점을 알려주고 있다. **네가 스스로 자동화할
   수 있는 부분을 극대화**해 봐."

## 1. 시황 브리핑 — 무엇을 만들었나

### 설계: 세 층을 섞지 않는다

| 층 | 누가 만드나 | 범위 | 주기 |
|---|---|---|---|
| ① 거시 해설 | AI (Sonnet 5.5) | **전 사용자 공용** | 하루 2회 |
| ② 내 종목 연결 | **서버 계산** (AI 아님) | 개인 | 화면 열 때마다 |
| ③ AI 한 줄 | AI (Haiku 5.5) | 개인 | 하루 2회 |

②를 AI 에게 시키지 않은 이유: "금리가 올랐다 → 내 성장주 비중이 61.4%"는 **계산**이다.
계산할 수 있는 것을 AI 에게 맡기면 **틀릴 수 있는 형태로 바꾸는 것**이다.
화면에도 "이 숫자는 AI 가 아니라 서버가 센 값"이라고 적는다 — 출처가 다르면
믿는 정도도 달라야 한다.

## 2. 비용 산정

단가 기준: 2026-11-05 Anthropic 1st-party API (`claude-sonnet-5-5` $2 / $10 per MTok,
`claude-haiku-5-5` $0.10 / $0.50 per MTok).

### 토큰 추정

| 호출 | 모델 | 입력 | 출력 | 1회 |
|---|---|---|---|---|
| 장 전 거시 (검색 3회 포함) | Sonnet 5.5 | ~6,000 | ~1,100 | $0.023 |
| 장 후 거시 (검색 없음) | Sonnet 5.5 | ~2,200 | ~1,000 | $0.014 |
| 개인 한 줄 × 사용자 1인 | Haiku 5.5 | ~900 | ~250 | $0.0002 |

> 장 전 입력이 큰 이유는 **웹 검색 결과가 입력 토큰으로 다시 들어오기** 때문이다.
> 검색 도구에는 토큰과 **별도로** 건당 요금이 붙는다 — **1,000회당 $10**(= 1회 $0.01).
> `max_searches=3` 이므로 장 전 1회당 검색비는 최대 $0.03 이다.
> 실제로는 모델이 필요한 만큼만 쓰므로(단순 사실 조회는 1~3회) 보통 그보다 적다.
> 오류가 난 검색은 과금되지 않는다.

### 월 비용 (사용자 1명)

```
장 전  (토큰 $0.023 + 검색 최대 $0.03) × 30일 = $1.59   ← 상한
장 후  $0.014 × 30일                          = $0.42
개인    $0.0002 × 2회 × 30일                   = $0.012
──────────────────────────────────────────────────────
합계   월 $2.0 (상한) · 검색을 평균 1회만 쓰면 월 $1.4
```

검색비를 더 줄이려면 `max_searches` 를 3 → 2 로 내리면 된다
(`_gen_macro_brief` 안 한 곳). 다만 CPI·기준금리·다음 일정 **세 가지**를 묻고
있으므로 2로 내리면 셋 중 하나는 '확인 필요'로 남을 가능성이 커진다.

사용자가 늘어도 ①②는 **안 는다**(공용·계산). 느는 것은 ③뿐이고,
10명이 되어도 월 $0.12 다.

### 현재 지출과의 비교

| 항목 | 월 |
|---|---|
| 기존 — 매일 07:30 전략 리포트 cron | 약 $1.8 |
| **신규 — 시황 브리핑** | **$1.4 ~ $2.0** |
| 합계 | **$3.2 ~ $3.8** |

> 종목 분석은 오너 PC 의 Claude Code 구독으로 돌고 있어 한계비용 0 이다
> (2026-08-20 이전). 이 표에 없다.

### 돈이 새지 않게 박아 둔 것 (테스트로 지킨다)

- `/api/market/brief` 는 **읽기 전용**. 모델을 부르지 않는다.
  탭을 열 때마다 모델을 부르면 열어 본 횟수만큼 돈이 나간다.
  → `test_read_endpoint_never_calls_the_model`
- 같은 세션을 두 번 요청하면 서버가 건너뛴다(`already_exists`).
  cron 이 겹쳐 돌아도 돈이 두 번 안 나간다. **중복 검사가 생성보다 앞**에 있다.
  → `test_cron_skips_when_session_already_exists`
- 웹 검색은 장 전 세션만. → `test_only_pre_session_uses_web_search`
- 사용자 수만큼 도는 호출(③)은 가벼운 모델만. → `test_personal_note_uses_the_light_model`

## 3. 오너가 해야 하는 일 — cron 등록

원격 셸 쓰기 권한이 없어 **스크립트 설치만 못 했다.** 아래 두 줄이면 끝난다.

```bash
# 1) 스크립트 설치 (리포의 scripts/daon-macro-brief.sh)
scp -i ~/oracle-key.key scripts/daon-macro-brief.sh ubuntu@168.107.13.20:/tmp/
ssh -i ~/oracle-key.key ubuntu@168.107.13.20 \
  "sudo install -m 755 /tmp/daon-macro-brief.sh /usr/local/bin/daon-macro-brief.sh"

# 2) crontab -e 에 두 줄 추가
10 22 * * * /usr/local/bin/daon-macro-brief.sh   # KST 07:10 장 전 (검색 포함)
0  7  * * * /usr/local/bin/daon-macro-brief.sh   # KST 16:00 장 후 (검색 없음)
```

**등록 전에도 볼 수 있다.** 시장 탭 '오늘의 시황' 카드 오른쪽의 **[지금 만들기]**
버튼(관리자만 보임)을 누르면 즉시 생성된다. 같은 세션은 건너뛰므로 연타해도
돈이 한 번만 나간다.

## 4. 자동화 계획 — "내가 검색해서 알려주는 것"을 없애기

오너의 지적이 정확하다. 지금 개선 아이디어의 유입 경로는 **오너 한 사람**이고,
그 사람이 바쁘면 앱은 조용히 늙는다. 이미 깔려 있는 것과 빈 곳을 가른다.

### 이미 도는 것

| 무엇 | 어디서 | 주기 | 상태 |
|---|---|---|---|
| 데일리 브리핑 (6축 뉴스) | 클라우드 | 매일 07:00 | ● 돈다 |
| 집현전 주간 종합 | 클라우드 | 매주 월 07:00 | ● 돈다 |
| 발굴 GARP 스캔 | 서버 cron | 매일 07:00 | ● 돈다 |
| 전략 리포트 갱신 | 서버 cron | 매일 07:30 | ● 돈다 |
| 종목 AI 분석 | 오너 PC 스케줄러 | 매일 | ● 돈다 (구독, 비용 0) |
| **시황 브리핑** | 서버 cron | 하루 2회 | ◐ **코드 완료, cron 미등록** |

### 비어 있는 곳 — 제안 3개

#### 제안 A. `daon-radar` 를 주간 클라우드 예약으로 (가장 큰 효과)

`daon/.claude/skills/daon-radar` 는 **이미 있다.** 바깥(논문·앱·서비스·기사)에서
배우고 안(첫사용 UX·개인정보·답변품질)을 점검해 `docs/RADAR.md` 에 로드맵 항목이나
'명시적 기각'으로 남기는 루프다. 그런데 **오너가 "레이더 돌려"라고 해야만 돈다.**

→ 집현전 주간 종합과 같은 방식으로 클라우드 예약에 올린다. 매주 월요일,
   PC 가 꺼져 있어도 돈다. 결과는 `docs/RADAR.md` 에 쌓이고 오너는 **읽기만** 한다.

비용: 클라우드 에이전트 1회/주. 오너 확인 필요 — 예약 작업은 되돌리기 전에
계속 돈이 나가는 약속이라 내가 임의로 걸지 않았다.

#### 제안 B. 경쟁 앱 기능 추적을 레이더 항목으로 고정

오너: "여러 한국 증권사가 앞다투어 AI 종목 추천 기능을 탑재했다. 트렌드를 참조해
좋은 기능은 적기에 반영하자."

→ `daon-radar` 의 '바깥' 수집 대상에 **국내 증권 앱 6곳(토스증권·키움·미래에셋·
삼성증권·NH·카카오페이증권)의 AI 기능 변경**을 고정 항목으로 넣는다.
매주 "이번 주 새로 생긴 것 / 우리에게 있는 것 / 우리가 일부러 안 하는 것" 3열로.

🟥 **베끼지 않는다.** 레이더의 산출물은 '기능 목록'이 아니라
**"이 기능이 어떤 화면에서 무엇을 덜어내는가"** 여야 한다 — 토스증권 벤치마킹의
기준이 그것이다. 덜어내는 것이 없으면 '명시적 기각'으로 적고 넘어간다.

#### 제안 C. 앱이 스스로 "안 쓰이는 화면"을 신고하게

이미 `TabUsagePanel`(탭 사용량)이 있다. 지금은 보기만 한다.
→ 주간 레이더가 이 숫자를 읽고 **4주 연속 0회인 화면**을 "뺄 후보"로 올린다.
   기능을 더하는 제안만 쌓이면 앱은 한 방향으로만 자란다.

### 내가 **지금** 걸지 않은 이유

예약 작업은 "한 번 승인 = 계속 돈이 나가는 약속"이다. 오너가 명시적으로
승인하지 않은 반복 비용을 내가 만들지 않는다. 제안 A·B·C 는 **한 번 "걸어"라고만
하면** 그 자리에서 건다.
